## 1. Fixing the TUI/CLI rendering

Your `markdown.ts` + `tui.ts` already have solid bones (grapheme-aware wrapping, diff-based frame rendering, boxed messages) — what's missing is the stuff that makes Claude Code/Codex *feel* polished:

**a) Syntax-highlighted code blocks** (right now code blocks just get a flat background + one color per language). Add a lightweight tokenizer to `markdown.ts`:

```ts
const KEYWORDS: Record<string, RegExp> = {
	ts: /\b(const|let|var|function|return|if|else|for|while|import|export|async|await|class|interface|type|extends|implements|new|this|typeof|as|from)\b/g,
	js: /\b(const|let|var|function|return|if|else|for|while|import|export|async|await|class|new|this|typeof)\b/g,
	py: /\b(def|return|if|elif|else|for|while|import|from|class|as|with|try|except|async|await|lambda)\b/g,
	bash: /\b(if|then|fi|for|do|done|echo|export|function)\b/g,
};

function highlightLine(line: string, lang: string): string {
	const kw = KEYWORDS[lang];
	let out = line;
	// strings first so keywords inside them aren't touched
	out = out.replace(/(["'`])(?:(?!\1).)*\1/g, (m) => `${FG_GREEN}${m}${RESET}${BG_DIM}`);
	out = out.replace(/\/\/.*$|#.*$/g, (m) => `${DIM}${m}${RESET}${BG_DIM}`);
	if (kw) out = out.replace(kw, (m) => `${FG_YELLOW}${m}${RESET}${BG_DIM}`);
	return out;
}
```

Then in `renderMarkdownColored`, when emitting `blockLines`, call `highlightLine(bl, lang)` instead of the flat color. It's not a full grammar, but regex-level highlighting gets you 80% of the visual win for near-zero cost/deps.

**b) Diff rendering for `edit`/`write` tool results** — this is the single biggest "looks like a real coding agent" upgrade. Right now `summarizeToolResult` just prints "edited". Have `editTool`/`writeTool` return a unified-diff-ish preview in `details`, and render it in `tui.ts`:

```ts
function renderDiffLines(oldText: string, newText: string, width: number): string[] {
	const oldLines = oldText.split("\n");
	const newLines = newText.split("\n");
	const out: string[] = [];
	// crude line diff is fine for chat display — full Myers diff is overkill
	for (const l of oldLines) if (!newLines.includes(l)) out.push(truncateToWidth(`${RED}- ${l}${RESET}`, width));
	for (const l of newLines) if (!oldLines.includes(l)) out.push(truncateToWidth(`${GREEN}+ ${l}${RESET}`, width));
	return out;
}
```

Wire this into `tool_execution_end` handling for `edit`/`write` in `tui.ts`, appended under the `✓ edit path.ts` line, capped at ~10 lines.

**c) Hyperlinks (OSC 8)** — URLs in assistant text (docs links, file paths) should be clickable:

```ts
function osc8Link(url: string, label = url): string {
	return `\x1b]8;;${url}\x1b\\${label}\x1b]8;;\x1b\\`;
}
```
Apply to `\bhttps?:\/\/\S+\b` matches in `renderAssistantText`.

**d) Tables** — `markdown.ts` has no `| a | b |` support at all; add a case in `renderMarkdown` that detects a `---|---` separator line and box-draws a table. Low priority unless the model outputs tables often.

Priority order I'd actually do this in: **(b) diffs → (a) highlighting → (c) links → (d) tables**. Diffs are what makes edits legible; the rest is polish.

## 2. `/init` — personal profile

Model it on Claude Code's `/init`, but pointed at *you* instead of the repo. Two pieces: a profile file + a slash command that bootstraps it conversationally (reusing your existing `write`/`read` tools instead of building new plumbing).

**`src/profile.ts`** (new file):
```ts
import { promises as fs } from "node:fs";
import os from "node:os";
import path from "node:path";

export function profileDir(): string {
	return process.env.FRIDAY_NG_CONFIG_DIR ?? path.join(os.homedir(), ".friday-ng");
}
export function profilePath(): string {
	return path.join(profileDir(), "PROFILE.md");
}
export async function loadProfile(): Promise<string | undefined> {
	try {
		return await fs.readFile(profilePath(), "utf8");
	} catch {
		return undefined;
	}
}
```

**Slash command** (`commands/builtin.ts`):
```ts
export function makeInitCommand(deps: { hasProfile: () => Promise<boolean>; dir: string }): SlashCommand {
	return {
		name: "/init",
		description: "Set up or update your personal profile (name, preferences, current projects).",
		run: async (): Promise<SlashCommandResult> => {
			const exists = await deps.hasProfile();
			const prompt = exists
				? `Read PROFILE.md (root: "${deps.dir}") with the read tool, summarize it for me, ask what's changed, then rewrite it with the write tool (same root) once I confirm.`
				: `Interview me one question at a time — name, role, how I like explanations (terse vs detailed), tone, current projects, anything else worth remembering. When done, write a concise Markdown PROFILE.md via the write tool with root "${deps.dir}" and path "PROFILE.md".`;
			return { submitFollowUp: prompt };
		},
	};
}
```

Important gotcha: `writeTool` restricts writes to inside `root` (defaults to `process.cwd()`). Pass `root: profileDir()` explicitly in the prompt (as above) or the safety check in `path-safety.ts` will reject the absolute home-dir path.

**Wire it into `cli.ts`**: register the command next to the others, and make `buildSystemPrompt` async so it injects the profile every session:

```ts
async function buildSystemPrompt(modelId: string): Promise<string> {
	const profile = await loadProfile();
	return (
		`You are friday-ng, a next-generation AI assistant with instant token streaming. ` +
		`Current model: ${modelId}. Be helpful, concise, and friendly.` +
		(profile ? `\n\n## About the user\n${profile}\n` : "") +
		buildEnvironmentContext()
	);
}
```
(you'll need to `await` the two call sites in `main()`/`runRepl()`.)

One more nicety: also support a **project-level** file (`./AGENTS.md` in cwd, like CLAUDE.md) loaded alongside the global `PROFILE.md` — global = who you are, project file = what this codebase is. Same loader pattern, just `path.join(process.cwd(), "AGENTS.md")`.
