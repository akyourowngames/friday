feat(tools): massively stronger websearch — DDG HTML, Tavily, SearXNG, refined output

The existing websearch tool was hitting DuckDuckGo's Instant Answer
API and falling back to Wikipedia. That gave "no results" on most
real queries because the Instant Answer endpoint only fires for
well-known topics. This commit replaces the chain with five
real providers, parallel race, and a refined model-facing output.

New providers (in race order, only the keyless ones run by default):
  1. DuckDuckGo HTML  - scrapes the lite HTML endpoint; real top-10
                          web results, no key, no rate limit.
  2. Tavily            - AI-native search, returns a synthesized answer
                          plus cited sources. Requires an API key
                          (free tier at tavily.com, 1000 queries/mo).
  3. SearXNG           - metasearch engine; user-configurable instance
                          URL (defaults to none; user opts in via the
                          new "API keys" section in settings).
  4. DDG Instant Answer - original JSON path, kept for backward compat.
  5. Wikipedia opensearch - final fallback, always available.

The model now receives:
  - a `Summary:` line (from Tavily, when configured)
  - a numbered list of `References` with title, URL, snippet
  - a `Sources consulted:` footer listing which providers contributed
    and how long each took

Tool output also carries a `details` payload with structured
results, the answer string, and the per-provider source table, so
the UI can render a citation card instead of dumping raw text.

Refined model output is produced by `formatSearchResults()` and
unit-tested in `tests/websearch.test.ts` (15 cases — up from 7).

New `websearchToolWith(config)` helper binds a user's Tavily key +
SearXNG URL into a fresh tool instance. The web Route Handler
constructs the tool with the user's settings on every chat request.

Settings + UI
- `src/settings.ts` adds new setting keys: `tavilyApiKey` (secret),
  `braveApiKey` (secret, for future use), `searxngUrl` (url), and
  `websearchRecency` (enum). New `SettingType` values: `secret` and
  `url`. New `group` + `hintUrl` fields for the modal.
- `validateValue()` now handles `secret` and `url` as strings.
- The web Settings modal groups settings by `group` and adds a
  dedicated "API keys & search providers" section with a show/hide
  eye toggle for secrets, hint links to provider sign-up pages,
  and a storage location hint.
- `web/src/components/chat/SearchCard.tsx` (new) renders websearch
  results as a card with the query in the header, the summary,
  numbered references, and a "Sources consulted" footer. Wired
  into `MessageBubble` so `websearch` tool runs use it instead of
  the generic `ToolCard`.
- `useChatSession` reads `details.results/answer/sources/provider`
  off the `tool_execution_end` event and stores them on the
  `ToolRun` for the UI to render.

Tests
- `tests/websearch.test.ts` covers each provider, the chain
  fallback order, deduplication across providers, abort handling,
  empty-query rejection, and the formatted model output.
- 474 / 474 tests pass (up from 460).

Verified
- `npx tsc --noEmit` clean (root + web)
- `next build` clean; page chunk grew 11.1 kB -> 12.5 kB
- `npm run web:dev` will now run websearch with whichever providers
  the user has configured; keyless users get DuckDuckGo HTML +
  Wikipedia, which is already a major upgrade over the old
  Instant-Answer-only behavior.
