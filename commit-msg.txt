feat(web): render assistant text as proper markdown, not raw source

The web chat was dumping the assistant's `message.text` into a
`<div>` with `white-space: pre-wrap`, so any `## heading`,
`- bullet`, or ` ```code block` from the model showed up as raw
markdown source text instead of formatted output. Same problem on
the user's first session - the model replied with a structure, and
the chat just printed the structure verbatim.

Adds `web/src/components/chat/MarkdownView.tsx` - a small React
component that uses the existing `renderMarkdown` parser
(`src/markdown.ts`, shared with the TUI) and turns the parsed
spans into proper semantic HTML:

- Headings (`<h1>`-`<h6>`) with a violet accent bar
- Bullets with indentation by nesting depth
- Ordered lists with colored index markers
- Block quotes with a left bar
- Fenced code blocks with monospace font + dim background
- Horizontal rules
- Tables (already supported by the parser)
- Inline `code`, `**bold**`, `*italic*`, and URLs (rendered as
  real `<a target="_blank">` tags)

`MessageBubble` now uses `MarkdownView` for assistant messages
and keeps the existing `pre-wrap` rendering for user messages,
which need newlines preserved as plain text.

Styles live in `app/globals.css` under `.harness-md*` selectors,
matching the dark/light theme tokens already in the design
system.

Verified:
- `next build` clean, page chunk grew 9.24 kB -> 11.1 kB
- 21 `.harness-md*` rules in the production CSS bundle
- `/api/chat` SSE stream still streams correctly with faux
- `renderMarkdown` already handles every streaming prefix
  (existing test `preserves every incomplete fenced and table
  streaming prefix` covers partial `## Over` and other
  mid-stream markdown states)
