# Code of Conduct

Ares is a local-first personal assistant project. Contributors are expected to keep the project respectful, useful, and safe for users.

## Our Standards

Good participation includes:

- Being respectful and direct.
- Giving constructive technical feedback.
- Assuming good intent while still reviewing carefully.
- Keeping discussions focused on the work.
- Respecting user privacy and local data.
- Being honest about bugs, risks, limitations, and test gaps.

Unacceptable behavior includes:

- Harassment, insults, threats, or personal attacks.
- Discriminatory language or behavior.
- Publishing private user data, secrets, logs, screenshots, or messages without permission.
- Deliberately submitting harmful code, hidden telemetry, credential theft, destructive behavior, or unsafe automation.
- Repeatedly ignoring maintainer guidance, review rules, or project safety boundaries.

## Technical Safety Expectations

Because Ares can run shell commands, edit files, store memory, use phone bridges, and call external services, contributors must be careful with:

- File deletion and overwrite flows.
- Shell/code execution.
- Phone calls, SMS, notifications, and contact data.
- Web requests and external providers.
- Memory extraction and storage.
- Config, token, and OAuth handling.

Do not weaken confirmation gates, privacy defaults, or safety checks without a reviewed design discussion.

## Reporting Problems

If you see behavior that violates this code:

1. Save relevant context.
2. Contact a maintainer privately when privacy or safety is involved.
3. Open a public issue only when it does not expose private data or security details.

Reports should include:

- What happened.
- Where it happened.
- Who was affected.
- Any links, screenshots, or logs that are safe to share.

## Enforcement

Maintainers may:

- Ask for edits to comments, issues, or pull requests.
- Close or lock discussions.
- Reject contributions.
- Block repeat offenders.
- Remove harmful content from the project.

Enforcement should be proportional, consistent, and focused on protecting contributors and users.
